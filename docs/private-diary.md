# Diário pedagógico privado — primeira fatia

O contrato histórico SCHEMA_DIARIO_PEDAGOGICO.md (blob c83300a) define entrada única pelo card, visão individual derivada, tarefas excluindo ausentes do denominador, observações factuais e decisão humana sobre contato. Preservamos entrada única e derivação; substituímos KV e espelho Git por D1 privado. Não copiamos exemplos reais, nomes, IDs históricos ou registros. A versão atual só registra frequência e evidência pedagógica de aprendizagem; não importa observações de comportamento/bem-estar, tarefas ou triagem de comunicação.

GET /api/v1/offers/:offer/lessons/:lesson/diary: lista alunos com matrícula ativa, status nulo quando não há registro; teacher somente. PUT .../attendance/:student: status present/absent/late/excused e revisão 0 para criação ou versão atual para alteração. POST .../evidence/:student: kind e observation até 500 caracteres, apenas evidências factuais. Ambas exigem encontro taught, matrícula ativa, teacher e mesma origem. POST não é idempotente; em falha ambígua consultar percurso antes de repetir. GET /api/v1/offers/:offer/students/:student/profile: contagens de frequência explicitamente registrada em aulas dadas e últimas 50 evidências da oferta; não classifica registro inexistente como ausência. Não calcula percentual oficial, alerta ou desempenho a partir de amostra incompleta. Matrículas sem datas de vigência impedem reconstruir denominador histórico; não usar como boletim. A avaliação continua na área separada. Não há endpoint para marcar aula dada, criar turma ou matrícula. Alteração de frequência tem revisão e auditoria de ator/alvo, não histórico completo de estados. Evidência guarda autor. Ações de escrita retornam linha SQL (RETURNING), não contagem meta que pode incluir efeitos de trigger; hipótese para a divergência de D1 no run 45451588226, a confirmar na próxima CI.

A interface privada abre diário pelo card da aula e percurso pelo aluno. Não há exportação de dados reais nem integração com Toddle, Drive ou comunicação automática. O diário não tem armazenamento local. Testes ampliados nos dois runtimes, ainda não homologados; interface visual/interativa pendente. Próximos passos: homologar D1, calendário/matrícula temporal, marcação de aula dada e registro coletivo, conferência de tarefa (completa/metade/não feita/ausente), política de correção e retenção de evidências, integração documental autorizada.
